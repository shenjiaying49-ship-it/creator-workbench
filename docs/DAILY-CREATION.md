# 每天一篇、五库驱动的创作台（2026-11-06 用户纠偏）

## PRD / 范围
用户需要的主产品是每天打开即有建议成稿，而非管理表格。每天准备1篇小红书母稿，是否发布由用户决定；右上角切换平台，其他版本按需生成。只产文字；图文用户配图，视频用户录制。

REQ-D1：飞书选题、范文、作品、复盘、规则单向映射到网页素材库；生成前强制拉最新五库，失败不使用旧规则偷偷生成。网页人工修订保存在本地版本，不默认改飞书原始素材。
REQ-D2：来源仅原监控清单与五库选题/范文。临时HN/GitHub泛热点不进入自动选题。优先当天确认排期；否则选未使用且符合账号定位的五库内容。外部线索无正文不自动成稿。
REQ-D3：三步AI：选择来源/形式/切入点→完整相关规则+完整匹配范文写作→逐项质量复核（网页由独立模型调用审稿；Codex备稿由当前Codex逐项复核并标明），最多一次修订。禁止固定先图文再改口播；缺平台规则明确阻断。保留置信度，待验证不能声称确定有效。
REQ-D4：保存每篇来源ID、规则全文和快照hash、范文全文、选用规律与应用说明、形式判断依据、质量检查。正文避免套用别人的经历或数字；范文结构迁移而非换词复制。质检失败标「待修改」，不标可发布。
REQ-D5：首页日期+今日稿件（标题/正文可改），右上角平台切换，形式建议及一句理由。长规则与来源折叠；辅助入口五库/排期复盘。明确加载/空/错误，切平台未保存先提示。保存修订有版本冲突保护。
REQ-D6：每天08:00由Codex heartbeat备1份母稿；需要本地Codex与项目文件可访问。每日最多一次自动尝试；失败显示错误，人工可重试；不覆盖人工修订。网页即时生成最多规划/写作/复核3次，失败最多加修订/复核2次；当前网关余额不足，此入口停用并显示原因。每日Codex直接备稿，通过brief()/accept_codex()读取真实上下文并验证保存，不依赖网页模型网关。

## DESIGN / 可审阅原型
static/index.html 为浅绿白纸文字编辑器，顶部日期和平台下拉。居中窄栏一篇稿，阅读宽度约760px；只显示形式理由、标题、正文、保存/复制/生成操作；依据另放details。空状态提供按五库准备，缺规则显示原因。手机单列，按钮换行。原排期与复盘入口移到 secondary-board.html。无需图片、视频、插画。

## ARCHITECTURE
沿用Python+原生JS。creation_desk.py 负责latest context、候选与规则路由、JSON校验、审稿、日稿版本与异步任务。data/daily_creations.json 为生成稿与编辑记录；data/creation_jobs.json 任务状态；五库仍由feishu_board同步。API /api/desk、/api/desk/generate、/api/desk/job、/api/desk/save、/api/desk/sync；人工生成后台线程避免卡住页面，锁禁止重复生成。旧studio/wuku生成入口阻断并引导统一工作台，禁止继续通用模板旁路。
监控配置使用config.json creator.monitor_sources_path 指向既有monitor_sources.json；公开RSS独立只读采集，不启动原监控脚本的消息推送。不读浏览器cookie。
